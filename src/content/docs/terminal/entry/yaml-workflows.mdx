## 功能介绍

工作流支持简便的参数化，并可按名称、描述或命令参数进行搜索。由 Warp 团队和社区整理的[常用工作流](https://github.com/warpdotdev/workflows)可在应用中直接使用。此外，你还可以在本地或 Git 仓库范围内创建和管理工作流。

## 如何使用

* 打开[命令搜索](/terminal/entry/command-search/)或工作流搜索 `CTRL-SHIFT-R` 面板来查找工作流。
* 进入菜单后，在搜索框中开始输入以过滤现有工作流（例如 git、android、npm 等）。
* 按 `ENTER` 选中工作流后，可使用 `SHIFT-TAB` 循环切换参数。
* 也可以用鼠标拖动右边缘来横向展开菜单。

:::note
你可以通过在 **Settings** > **Features** > **Workflows** 中关闭 "Show Global Workflows" 来定制[命令搜索](/terminal/entry/command-search/)体验。禁用后，搜索将仅包含 YAML 和 Warp Drive 工作流。
:::

### 与别名有何不同？

工作流解决了别名的一些主要痛点，具体包括：

1. 需要切换上下文
   1. 退出 vim、source dotfiles 或重置 shell
2. 难以附加文档说明
3. 无法轻松搜索或共享
4. 无法轻松参数化

## 创建自定义工作流

### 如何使用 YAML 创建工作流

你可以将本地工作流（仅限当前机器）保存在：

<Tabs>
  <TabItem label="macOS">
    ```bash
    $HOME/.warp/workflows/
    ```
  </TabItem>
  <TabItem label="Windows">
    ```powershell
    $env:APPDATA\warp\Warp\data\workflows\
    ```
  </TabItem>
  <TabItem label="Linux">
    ```bash
    ${XDG_DATA_HOME:-$HOME/.local/share}/warp-terminal/workflows/
    ```
  </TabItem>
</Tabs>

或者，你可以将工作流保存在 `{{path_to_git_repo}}/.warp/workflows/` 中与团队共享。本地和仓库工作流分别可在工作流菜单的 "My Workflows" 和 "Repository Workflows" 标签页下访问。

有关示例，请查看 [Workflows 仓库](https://github.com/warpdotdev/Workflows/tree/main/specs)中的工作流规范。文件格式说明如下：

<details>

<summary><a href="https://github.com/warpdotdev/Workflows/blob/main/FORMAT.md">工作流文件格式</a></summary>

工作流文件格式为 [yaml](https://yaml.org/) 文件，必须具有 \`.yml \` 或 \`yaml\` 扩展名。如果你是 YAML 新手并想了解更多，请参阅 [Learn YAML in Y minutes](https://learnxinyminutes.com/docs/yaml/)。

---

**`name`**

工作流的名称。必填。

**`command`**

选中工作流时执行的命令。必填。

**`tags`**

用于对工作流进行分类的标签数组。可选。

```yaml
tags: ["git", "GitHub"]
```

**`description`**

工作流的描述及其用途。可选。

**`source_url`**

工作流最初生成来源的 URL。此字段在 [commands.dev](https://www.commands.dev/) 中用于注明出处。可选。

**`author`**

工作流的原始作者。例如，如果此工作流来自 StackOverflow，则 `author` 为该 StackOverflow 帖子的作者。此字段在 [commands.dev](https://www.commands.dev/) 中用于注明出处。可选。

**`author_url`**

工作流原始作者的 URL。例如，如果此工作流来自 StackOverflow，则 `author_url` 为该 StackOverflow 作者的个人主页。此字段在 [commands.dev](https://www.commands.dev/) 中用于注明出处。可选。

**`shells`**

此工作流有效的 shell 列表。如果未指定，则假定在所有 shell 中均有效。必须是 `zsh`、`bash` 或 `fish` 之一。

**`arguments`**

工作流可以包含参数化参数，以指定需要由用户填写的工作流部分。

你可以通过用两个花括号（`{{<argument>}}`）包裹来指定工作流命令中的哪个部分对应一个参数。

例如工作流命令：

```bash
for {{variable}} in {{sequence}}; do
  {{command}}
done
```

包含 3 个参数：`variable`、`sequence` 和 `command`。

**`arguments.name`**

参数的名称。参数名称在命令中用于指定参数的范围。必填。

```yaml
name: Example Workflow
command: echo {{string}}
arguments:
  - name: string
    description: The value to echo
```

**`arguments.description`**

参数的描述。此字段在 [commands.dev](https://www.commands.dev/) 和 Warp 中均有展示，以帮助用户填写工作流参数。可选。

**`arguments.default_value`**

参数的默认值。如果指定，则 `default_value` 会替换命令中的参数名称。可选。

---

</details>

### 工作流的保存位置

本地工作流仅限当前机器使用。仓库工作流的范围为某个 Git 仓库，克隆该仓库的所有人均可访问。

<Tabs>
  <TabItem label="macOS">
    ```bash
    # 本地工作流路径
    $HOME/.warp/workflows/

    # 仓库工作流路径
    {{path_to_git_repo}}/.warp/workflows
    ```
  </TabItem>
  <TabItem label="Windows">
    ```powershell
    # 本地工作流路径
    $env:APPDATA\warp\Warp\data\workflows\

    # 仓库工作流路径
    {{path_to_git_repo}}\.warp\workflows
    ```
  </TabItem>
  <TabItem label="Linux">
    ```bash
    # 本地工作流路径
    ${XDG_DATA_HOME:-$HOME/.local/share}/warp-terminal/workflows/

    # 仓库工作流路径
    {{path_to_git_repo}}/.warp/workflows
    ```
  </TabItem>
</Tabs>

#### 本地工作流

首先，在以下目录中创建工作流子目录：

<Tabs>
  <TabItem label="macOS">
    ```bash
    mkdir -p $HOME/.warp/workflows/
    ```
  </TabItem>
  <TabItem label="Windows">
    ```powershell
    New-Item -Path "$env:APPDATA\warp\Warp\data\workflows\" -ItemType Directory
    ```
  </TabItem>
  <TabItem label="Linux">
    ```bash
    mkdir -p ${XDG_DATA_HOME:-$HOME/.local/share}/warp-terminal/workflows/
    ```
  </TabItem>
</Tabs>

将工作流的 `.yaml` 文件添加到此目录；如果文件格式有效，Warp 会自动将其加载到工作流菜单中。

`cp ~/path/to/my_awesome_workflow.yaml {{path_to_local_workflow_folder}}`

#### 仓库工作流

添加仓库工作流的方式与添加本地工作流类似。在仓库根目录中创建 Workflows 文件夹，并按如下方式保存 `.yaml` 文件：

```
cd {{repository_path}}
mkdir -p .warp/workflows/
cp ~/path/to/my_awesome_workflow.yaml {{path_to_local_workflow_folder}}
```

#### 全局工作流

你可以通过 fork [Workflows 仓库](https://github.com/warpdotdev/workflows/tree/main/specs)并提交 pull request 来贡献对其他 Warp 用户可用的工作流。详情请参阅 [Contributing](https://github.com/warpdotdev/workflows#contributing) 部分。
